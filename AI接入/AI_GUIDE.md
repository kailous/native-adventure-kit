## 识别环境与任务

先区分：构建游戏、安装地图与数据、接入 MCP、生成私人插件、查询攻略、操作游戏。只执行使用者授权范围。能执行本机命令时使用本包真实入口；只有聊天能力时给出可操作步骤并明确自己无法验证。不要把生成文件称为安装成功，不把 HTTP 成功称为游戏操作成功。

当前布局：scripts/prepare_native.py 与 upstream.lock.json 在仓库外装配 MacNativeGames；skills/native-mod-build/ 提供构建指引；AI接入/ 保留 MCP 与插件辅助工具。map-client/ 提供地图源码，当前不携带 App 或 DataPacks，旧 Release 仅作历史记录。若独立读取这份文档，先让使用者提供包的位置，不猜原作者电脑路径。

## 接入规则

1. 阅读 MCP_USER_GUIDE.md 与 PLUGIN_GUIDE.md；先确认本机/容器/云端位置、客户端传输和认证能力。
2. 使用使用者自己地图工具提供的 URL 和凭据。传输为 Streamable HTTP `/mcp`，认证为 `Authorization: Bearer <地图服务令牌>`。保留复制配置中的额外请求头。
3. 本机 127.0.0.1 仅供同机访问。云端用使用者自己的 HTTPS 地址/平台支持的私有连接；本项目没有内置 OAuth，不编造 OAuth 端点、scope 或 tunnel ID。
4. 客户端配置格式各异。先查其当前官方文档；保留所有已有 MCP 项，只合并新配置；不把一个产品的 TOML/JSON 原样写进另一产品。
5. 不把实际密钥写入聊天、可分享插件、Git 或报告。用户登录/MFA/凭据输入由用户在受支持界面完成。确需私人连接文件，限制本机访问权限，不将其加入发布包。
6. 连接测试只做 initialize、notifications/initialized、tools/list，然后在用户要求下用 search_points 等只读查询。列出真实工具与参数，不把文档工具总数当作当前事实。

## 工具使用

优先按语义发现工具，不依赖宿主添加的前缀。始终读取当前 inputSchema 和必填参数。说明数据来源、时间和缺失项，不把空结果补成事实。

- 地图搜索：search_points；图层以 schema 的 s/k/d 为准。用返回的真实 id 调 get_point_guide，不能虚构点位编号。
- 攻略：保留原图文顺序和来源；图片 URL 无法展示时，用返回的 mediaId 调 get_guide_image；不拿搜索图或生成图替代。
- 进度：get_save_progress 是读取存档；unknown/缺样本不等同未完成。
- 位置/画面：get_live_position、get_game_frame 依赖正在运行的原生游戏。失败时明确离线或超时，不用旧帧、存档位置或桌面截图冒充当前游戏状态。
- 输入观察：保留 session/sequence、分页和缺口；物理按键位置不等同 Nintendo 按键名或实际动作。
- 移动、攻击、互动、数值锁定、许愿、天气、amiibo 等会改变游戏状态，只在用户明确要求后执行。接入测试不调用它们。先读状态，再用 schema 允许的有界参数；不自动重试超时写操作，先确认实际状态。
- 用户接管立即停止自动输入，不关闭用户游戏。不要声称存在自动导航执行、完整背包/穿戴同步或林克 3D 预览；这些功能已退役。

构建支持原生 TOTK 1.4.3，模拟器适配不在本次交付范围。数据包目前版本 1.0.0，不能据此声称地图/地形已针对 1.4.3 全量验收，地形覆盖仍不完整。

## 插件与兼容降级

MCP 连接和插件安装分别验证。有插件能力的宿主可按 PLUGIN_GUIDE.md 生成自己的私有插件；没有插件能力时，直接配置 MCP 并加载本文件也能使用。不声称所有 agent 支持同一种插件格式。仅支持 stdio 的宿主需明确支持的 HTTP 桥接器，本包不提供旧地图后台源码或可直接运行的 stdio 入口。

交付给使用者：本机改了哪些配置、备份在哪、是否真正初始化并列出工具、插件只是生成还是已安装、是否已授权/实测游戏操作。失败时报告原因，不关闭认证、不复用别人的云端桥接，不反复创建重复插件。
