# 上游合并与已有功能完整性门禁

本约束适用于本kit、其装配出的MacNativeGames源码以及配套地图客户端。固定提交和摘要只保证装配一致，不能替代功能完整性验收。当前功能名称及待验收状态见[42项维护基线](source-update-2026-10-30.md)，后续更新须维护同一基线，不用旧日期记录冒充新候选结果。

## 每次合并必须检查

- 范围包括上游同步、分支合并、cherry-pick、手工移植、冲突解决及固定提交/补丁/兼容输入变更；不得只验证新增功能、编译成功或测试总数。
- 合并前记录目标版本、两侧提交、补丁和源码指纹、全部在维护功能基线、既有缺陷及待验收项；保留用户工作，不重置源码、设置或存档。
- 合并后逐项核对入口、实现、协议、资源、配置持久化及实际交付产物。覆盖未打算修改的既有能力，以及原生游戏、地图、后端、HTTP/MCP、手机输入、直播/弹幕、数据包和构建装配的跨仓库链路。
- 原生独立源码与地图分别可构建；明确外部输入、默认占位素材与数据包边界，不依赖维护者电脑路径或旧临时产物。版本锁和兼容输入均固定来源与摘要，不自动跟随最新main，不猜测冲突。
- 保留耐久修改与材料/料理/胶囊99锁定所需最小字段、共用目录和游戏帧调度。网络线程只传有界请求/快照，平台地址、版本表、对象校验及游戏帧访问约束不因合并移除。
- 原生1.4.3为维护主线；已退役的完整背包、穿戴同步、3D预览、自动导航/执行不纳入已交付基线。模拟器适配及虚拟amiibo接入仍missing；原生通过不代表模拟器支持，也不扩大移植范围。

## 证据与禁止放行条件

为每个候选在仓库外的用户指定工作区保存：合并前后源码/补丁指纹、功能逐项结果、测试日志、构建和产物SHA-256、实际场景证据及配置/资源核对。区分源码审阅、宿主测试、离屏GPU、候选App游戏实测与用户确认，不能互相冒充。

任一已有功能丢失、退化、默认行为被意外改变，或必查项未完成时，禁止认定合并完成、合入稳定主线、公开Release或替换现有交付。可以提交候选分支、准备私有发布草稿和待验收产物，但必须保留缺项与原因。

不得通过删入口/测试、重置用户配置、默认关闭功能、改低验收标准或更新基线掩盖回归。发现缺失须修复并重跑受影响链路。功能确需改变或退役时须用户明确授权，记录范围、原因和后续处理。

游戏占用、输入或环境缺失不解除门禁；继续独立检查，剩余项保持待验收。缺自动化证据不等于未实现，缺历史样本也不等于当前游戏故障。不得将历史实测重标为新候选passed。

## 游戏与发布操作

遵守GameSlot单实例锁与用户接管约定。代理游戏测试使用512x288、右下角、禁止全屏；复制现有存档和对应account.uid到隔离目录，不在真实profile中验收，不为凑齐证据关闭用户游戏或启动第二实例。

源码包运行check_release.py检查实际目录/ZIP，独立地图另查构建、签名、依赖通知、凭据/数据包排除和实际场景。静态检查通过、固定源码装配通过或只有编译成功均不解除以上门禁。发布流程仍按[独立发布规则](split-releases.md)，两个Release先草稿核对；门禁未闭合时保持草稿，不自动公开、不改写历史或旧附件。
